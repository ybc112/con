# CON 伞下业绩看板

团队长伞下业绩的 Web 看板。合约只记录「直推（第一代）」数据，没有伞下聚合函数，
本服务链下递归遍历推荐树，把结果缓存后供页面展示。

- 只读链上数据，**不需要私钥，不发起任何交易**
- 爬取逻辑与仓库根的 `con-downline-report.cjs` 一致（已通过 30 项单元测试
  与本地链端到端验证），见 `crawler.cjs` 顶部注释中的三条正确性保证
- 访问控制由 `ACCESS_PASSWORD` 环境变量控制：**设了就要密码，留空则完全公开**
  （生产环境当前为公开模式，见 `CON看板部署说明.md` 第 6.2 节）

生产部署见仓库根目录的 `CON看板部署说明.md`。

## 本地运行

```bash
npm install
ACCESS_PASSWORD=你的密码 PORT=3030 node server.cjs   # 带密码
PORT=3030 node server.cjs                            # 不带密码 = 公开模式
# 打开 http://127.0.0.1:3030
```

## 环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `ACCESS_PASSWORD` | 空 | 留空 = 公开访问；设置后需要密码登录 |
| `PORT` | 3030 | 监听端口（仅绑定 127.0.0.1） |
| `DATA_DIR` | `./data` | 名单与缓存目录 |
| `CONTRACT` | 主网质押合约 | 质押合约地址 |
| `DEPTH` | 20 | 遍历深度 |
| `REFRESH_MINUTES` | 10 | 后台自动刷新间隔 |
| `RPC_URL` | 内置 3 个公共节点 | 自定义 RPC |

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/login` | 校验密码，下发 HttpOnly cookie |
| POST | `/api/logout` | 退出 |
| GET | `/api/session` | 检查登录状态 |
| GET | `/api/report` | 取缓存的报表（需登录） |
| POST | `/api/refresh` | 触发后台刷新（需登录，不阻塞） |

## 设计说明

- **浏览器永远读缓存**，爬取在后台跑。伞下人数上千时一轮爬取要几分钟，
  不能让页面请求去等。
- **爬取失败保留上一次成功结果**，只在页面顶部显示错误横幅 —— 结算场景下
  宁可展示旧数据并报警，也不能把看板清空让人误以为业绩归零。
- 会话令牌每次启动重新生成，重启后旧 cookie 自动失效。
